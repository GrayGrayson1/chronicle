# Player site

The `site/` folder is a static player companion hosted on GitHub Pages. It is read-only and always available, even when the host PC is off. The look follows Jace's "Player companion" design concept.

## What players see

- **Overview:** latest session with a read-aloud button (uses the browser's built-in speech), party inventory, open quests, a featured NPC profile (likes, last interaction, a remembered quote, connections), moments from the table, and a private note.
- **Sessions:** every approved recap, the quotes and entries from that night, and the transcript if the host chose to publish transcripts.
- **People, Places, Timeline, Quests, From the table:** the approved compendium, with wiki links between entries.
- **Inventory:** what is carried and by whom, plus items that were dropped, stored, given away or lost, and where.
- **Search:** instant search over recaps, entries and (if published) transcripts. It does not call an AI. For an answer written from the evidence, players use `/ask` in Discord.
- **My notes:** saved only in that browser. Nothing is uploaded.

## What gets published

Publishing uses the same visibility as a read-only share link:

| Included | Not included |
| --- | --- |
| Approved sessions: title, date, recap | Sessions awaiting review |
| Party-visible PCs, NPCs, places, factions, items, quests, events, moments, awards, quotes | Private or selected-visibility entries, all journals |
| Citation session + timestamp | Transcript text (unless `SITE_INCLUDE_TRANSCRIPTS=1`) |
| Entry images, up to 12 MB total | Discord user IDs (`playerSubject`), file paths, chat history, member keys, audio |

## Security model

- The repository and site are public. Only `site/data/<campaign>.json` holds campaign content, and it is encrypted: gzip, then AES-256-GCM with a key derived from `SITE_PASSPHRASE` via PBKDF2-SHA256 (310,000 iterations, random salt and IV per publish).
- `site/data/index.json` is not encrypted. It lists each campaign's title (the campaign name, or `SITE_TITLE`) and update time.
- The password is only as strong as what you pick. Use a few random words, share it in the campaign's Discord channel, and change it (then re-publish) if someone leaves the group. Old versions remain in git history under the old password.
- "Remember on this device" stores the password in that browser's local storage. "Lock" clears it.
- `SITE_PUBLIC=1` with no passphrase publishes unencrypted. Don't use it for a real campaign.

## Setup (host PC)

1. Clone the repository (see [GITHUB_SETUP.md](GITHUB_SETUP.md)) and run Chronicle from the clone.
2. Add to `.env`:
   ```dotenv
   SITE_PASSPHRASE=pick-a-few-random-words
   SITE_AUTO_PUBLISH=1
   SITE_GIT_PUSH=1
   SITE_URL=https://graygrayson1.github.io/chronicle/
   ```
3. Make sure `git push` works from that folder without prompting (GitHub Desktop or `gh auth login` sets this up).
4. Run `npm run register` once so the new `/publish` command appears in Discord.
5. Approve a session review. Chronicle writes `site/data/`, commits only those files, pushes, and posts the link in the campaign channel. GitHub Pages updates about a minute later.

`/publish` (Manage Server) publishes on demand. `npm run publish-site -- "<campaign name>"` does it from a terminal while the bot is stopped; add `--no-push` to only write the files.

If a push is rejected because the repository moved ahead, run `git pull` in the Chronicle folder and publish again. Publishing never commits other changes in the working tree.

## Previewing

- Open the deployed site with `?demo` to see a fictional campaign (`site/demo.json`, generated by `node scripts/demo-site.js` through the real publish code).
- Locally: `cd site && python -m http.server 8000`, then open http://localhost:8000/?demo.

## Discord Activity (later)

The site uses only relative paths and no server, so it can be wrapped as a Discord Activity (opened inside a voice channel) by pointing the Activity's URL mapping at the GitHub Pages address. That is not set up yet. Unverified Activities only launch in servers under 25 members, and each player must be added as an app tester.
